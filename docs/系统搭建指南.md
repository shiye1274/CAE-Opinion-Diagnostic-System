# 系统搭建指南（GreenSilk-Monitor v0.5）

> 系统三件套已建好并实测可跑：**数据库（SQLite 四表，collector 已产出）→ 后端（FastAPI，已验证）→ 前端（React+AntD+ECharts 源码）**
> 本文说明启动顺序、架构、以及二期向 PostgreSQL / 微调模型接入的升级路径。

---

## 一、架构总览

```
前端 (React 5173)  --/api-->  后端 (FastAPI 8000)  --SQL-->  语料库 (corpus.sqlite)
      │                            │
      │ Vite dev proxy 转发        ├── /stats/*        大屏聚合
      │                            ├── /documents      语料检索 + 详情
      │                            ├── /kwic           KWIC 索引行
      │                            ├── /brands/volume  品牌声量（读词包 YAML）
      │                            └── /compliance/check  文化合规规则引擎
      │
      └── 生产部署时：Vite build → Nginx 静态托管 + 反代 /api
```

**v0.5 的聪明之处**：后端直接复用 collector 的 `packs/*.yaml`（品牌词包）和 `corpus.sqlite`（四表），数据更新 = 重新跑爬虫 + pipeline，前端零改动。

## 二、启动步骤（每天演示前）

```bash
# 终端 1：后端（在 backend/ 目录）
pip install -r backend/requirements.txt     # 首次
cd backend
uvicorn app.main:app --reload --port 8000
# 验证：浏览器开 http://localhost:8000/docs 可看到 Swagger

# 终端 2：前端（在 frontend/ 目录）
cd frontend
npm install                                  # 首次
npm run dev
# 打开 http://localhost:5173
```

先确保语料库有数据（`collector/` 里跑过 `run_trial.py` + `pipeline.py`）。

## 三、数据库设计（已实现）

| 表 | 用途 | 关键字段 |
|---|---|---|
| `corpus_documents` | 文档主表 | doc_id PK, source_id, language, lang_variant(MSA/Khaliji/Arabizi/EN/ZH), country, text_clean, sha256 |
| `doc_entities` | 品牌-文档映射 | brand_id, role_in_doc(CORE/BENCHMARK/PASSING) |
| `ugc_threads` | 评论树 | author_hash(脱敏), dialect_tag, stance_towards_cn_brand |
| `corpus_spans_annotations` | 段落级标注（预留） | sentiment_5scale, misreading_type, annotator_source |

**升级路径**：SQLite → PostgreSQL 只需改 `backend/app/core/db.py` 的连接函数（SQL 语法基本兼容），其余代码不动。触发时机：并发用户 >5 或数据 >50 万条。

## 七、常见问题

- **前端 /api 404**：后端没启动，或没走 Vite dev server（proxy 只在 `npm run dev` 生效）。
- **接口返回空/500**：先确认 `corpus/meta/corpus.sqlite` 存在且有 corpus_documents 数据（跑过 pipeline）。
- **阿语显示乱码**：确保浏览器 UTF-8；KWIC 阿语行已做 RTL 排版。
- **换电脑演示**：拷贝整个项目 + `pip install` + `npm install`，无需其他环境。
