# 数据包交接规范（A ↔ B）

> 原则：**代码走 Git，数据走微信/网盘**。本规范确保 B 每次传回的数据包能被 A 一键 `pipeline.py`  ingestion，且可追溯、可回滚。

## 1. 文件命名

```
corpus_raw_B_YYYYMMDD.zip
corpus_raw_B_YYYYMMDD_序号.zip   # 同一天多次提交
```

示例：
- `corpus_raw_B_20261125.zip`
- `corpus_raw_B_20261125_2.zip`

禁止：
- 不要含 `(1)`、`副本`、`新建文件夹` 等无法解析的后缀。
- 不要用中文日期。

## 2. ZIP 内部结构

```
corpus_raw_B_20261125.zip
├── manifest.json
├── raw/
│   ├── googlenews/
│   │   └── ... (jsonl / csv)
│   ├── youtube_api/
│   │   └── ...
│   ├── reddit/
│   │   └── ...
│   └── ...
└── README.txt (可选：特殊说明)
```

### 2.1 `manifest.json` 必填字段

```json
{
  "package_id": "corpus_raw_B_20261125",
  "owner": "B",
  "created_at": "2026-11-25T14:30:00+08:00",
  "sources": [
    {
      "source_id": "youtube_kw_ar",
      "adapter": "yt_dlp",
      "layer": "L4",
      "language": "ar",
      "files": ["raw/youtube_kw_ar/records.jsonl"],
      "records": 15234,
      "notes": "评论已脱敏"
    },
    {
      "source_id": "reddit",
      "adapter": "reddit_api",
      "layer": "L5",
      "language": "en",
      "files": ["raw/reddit/threads.jsonl"],
      "records": 892,
      "notes": ""
    }
  ],
  "total_records": 16126,
  "checksum": {
    "algorithm": "sha256",
    "value": "a1b2c3d4..."
  }
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `package_id` | 是 | 与 zip 文件名一致 |
| `owner` | 是 | 数据所有者，固定 `B` |
| `created_at` | 是 | ISO 8601 时间戳 |
| `sources` | 是 | 每个源一条 |
| `sources.source_id` | 是 | 必须能在 `collector/sources.yaml` 中找到对应 `id` |
| `sources.adapter` | 是 | 使用的适配器名 |
| `sources.layer` | 是 | L1-L5 |
| `sources.language` | 是 | `ar` / `en` / `zh` / `auto` |
| `sources.files` | 是 | 相对路径数组 |
| `sources.records` | 是 | 该源原始记录数 |
| `sources.notes` | 否 | 特殊说明（如脱敏、已知问题） |
| `total_records` | 是 | 全包记录总数 |
| `checksum` | 推荐 | SHA-256，用于校验完整性 |

### 2.2 原始数据文件格式

推荐统一为 **JSON Lines（.jsonl）**，每行一条记录，字段如下：

```json
{
  "source_id": "youtube_kw_ar",
  "layer": "L5",
  "language": "ar",
  "country": "SA",
  "url": "https://www.youtube.com/watch?v=xxx",
  "title": "...",
  "text": "...",
  "published": "2026-11-20 08:30:00",
  "content_type": "comment",
  "extra": {
    "video_id": "xxx",
    "author_hash": "sha256:...",
    "origin_query": "..."
  }
}
```

CSV 也可接受，但必须含 `source_id, layer, language, country, url, title, text, published` 列。

## 3. 数据预处理要求（B 负责）

### 3.1 必须做

- [ ] **PII 脱敏**：邮箱、手机号、真实用户名替换为占位符或哈希。
- [ ] **作者哈希化**：所有作者字段统一使用 `sha256:...` 前 16 位。
- [ ] **时间标准化**：尽量转换为 `YYYY-MM-DD HH:MM:SS`；时区不明则保留原值。
- [ ] **去重前置**：同一批次内做 URL/内容哈希去重，避免传重复数据。
- [ ] **字段完整性**：`text` 不能为空；`title` 缺失时用 `text[:80]` 填充。

### 3.2 禁止做

- 不要删除 `url`（回源审计需要）。
- 不要对正文做摘要/截断（pipeline 会按 word_count 过滤）。
- 不要混入 A 已经跑过的源（如 A 负责的 GDELT），除非明确说明是补充。

## 4. A 侧接收流程

收到 zip 后按以下 SOP 执行：

```powershell
# 1. 解压到固定目录
corpus/_incoming_B_20261125/

# 2. 校验 manifest
check_manifest.py --zip corpus_raw_B_20261125.zip

# 3. 备份当前 corpus.sqlite
Copy-Item corpus\meta\corpus.sqlite corpus\meta\corpus.sqlite.bak.20261125

# 4. 跑 ingestion
python -X utf8 collector\merge_b_1125.py --input corpus\_incoming_B_20261125\raw

# 5. 跑 pipeline 清洗/去重/门禁
python -X utf8 collector\pipeline.py

# 6. 生成门禁报告
cat collector\audit\gate_report_*.json

# 7. 提交代码变更（不提交 records.jsonl 或 zip）
git add collector\ docs\ *.py
git commit -m "data: merge B 2026-11-25 package (X records)"
git push
```

## 6. 单包大小与分卷

| 场景 | 建议 |
|---|---|
| 单包 < 100 MB | 直接微信发送 |
| 100 MB - 500 MB | 百度网盘/阿里云盘，微信只发链接 |
| > 500 MB | 必须分卷压缩，每卷 ≤ 200 MB |

微信限制：文件 ≤ 1 GB，但大文件容易中断。建议 routinely 分卷 ≤ 200 MB。

## 7. 版本与回滚

- 每次 ingestion 前 A 必须备份 `corpus.sqlite`。
- 命名：`corpus.sqlite.bak.YYYYMMDD`。
- 若新数据导致门禁倒退（如阿语比被稀释太多），A 可回滚备份，并与 B 协商调整该批次。

## 8. 问题反馈模板

B 传数据前如有异常，按以下格式发给 A：

```
源：youtube_kw_ar
问题：yt-dlp 大量 "Sign in to confirm you're not a bot"
影响：预计损失 60% 评论
已尝试：换代理、降速
需要：A 提供 Cookie / 或改期到明天
```
