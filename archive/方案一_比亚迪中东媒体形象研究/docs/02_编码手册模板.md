# 编码手册模板 v1.0
## 中东媒体报道品牌形象语料库编码手册

---

## 一、手册说明

本编码手册用于对中东媒体报道比亚迪（BYD）与特斯拉（Tesla）的语料进行人工编码。所有编码员在正式编码前必须通读本手册，并完成预编码培训。

### 1.1 编码原则

- **基于证据**：每个编码判断必须基于报道中的具体文本；
- **一致性**：同一编码员在不同时期编码同一报道时应保持一致；
- **双人独立编码**：每篇报道由两名编码员独立编码，争议协商解决；
- **边界案例**：遇到无法判断的情况，使用"无法判断"选项，不强行归类。

### 1.2 编码流程

1. 阅读编码手册
2. 预编码 50 篇（每子库约 10-15 篇）
3. 计算 Cohen's Kappa（κ ≥ 0.70）
4. 若 κ < 0.70，修订手册并重新培训
5. 正式编码
6. 随机抽查 10% 复核

## 二、元数据编码

### 2.1 文档编号（doc_id）

**规则**：`品牌_语言_序号`

| 代码 | 含义 |
|------|------|
| BYD | 比亚迪 |
| TESLA | 特斯拉 |
| AR | 阿拉伯语 |
| EN | 英语 |

**示例**：BYD_AR_001、TESLA_EN_042

---

### 2.2 品牌（brand）

| 值 | 定义 |
|----|------|
| BYD | 报道核心涉及比亚迪 |
| TESLA | 报道核心涉及特斯拉 |
| BOTH | 同时平等涉及两者 |
| OTHER | 涉及其他品牌（排除） |

**判定规则**：
- 标题或首段明确提及的品牌为"核心涉及"；
- 仅作为背景提及的品牌为"其他"；
- 若两品牌均占主要篇幅，编码为"BOTH"。

---

### 2.3 语言（language）

| 值 | 定义 |
|----|------|
| Arabic | 报道正文为阿拉伯语 |
| English | 报道正文为英语 |
| Other | 其他语言（排除） |

**注意**：标题语言可能与正文不同，以正文语言为准。

---

### 2.4 媒体来源（source）

**规则**：填写媒体机构正式名称（英文或阿语）。

**示例**：
- Arabic: العربية / Al Arabiya
- Arabic: البيان / Al Bayan
- English: Gulf News

---

### 2.5 媒体层级（source_tier）

| 值 | 定义 | 示例 |
|----|------|------|
| T1_AR_LOCAL | 阿语本地主流媒体 | Al Arabiya, Al Bayan, Okaz |
| T2_AR_PANARAB | 阿语泛阿拉伯/国际媒体 | Al Jazeera Arabic, Asharq Al-Awsat |
| T3_EN_GCC | 英语 GCC 本地媒体 | Gulf News, Khaleej Times |
| T4_EN_INTL | 英语国际媒体中东版 | Reuters ME, Bloomberg ME |

---

### 2.6 国家（country）

| 值 | 定义 |
|----|------|
| UAE | 阿联酋 |
| Saudi | 沙特阿拉伯 |
| Qatar | 卡塔尔 |
| Kuwait | 科威特 |
| Oman | 阿曼 |
| Bahrain | 巴林 |
| PanArab | 泛阿拉伯（非单一国家） |
| Other | 其他 |

**判定规则**：以媒体总部/主要运营国家为准。

---

### 2.7 发布日期（date）

**格式**：YYYY-MM-DD

**示例**：2024-03-15

---

### 2.8 文章链接（url）

**规则**：填写报道的永久链接（URL）。

---

### 2.9 网页存档链接（archive_url）

**规则**：填写 Wayback Machine 或其他存档链接（如有）。

## 三、内容编码

### 3.1 品牌指涉层级（referent_level）

**定义**：报道中品牌被指向的层级。

| 值 | 定义 | 示例 |
|----|------|------|
| CORPORATE | 企业形象 | "BYD 公司宣布扩张计划" |
| PRODUCT_BRAND | 产品品牌 | "BYD 品牌在中东获得好评" |
| SPECIFIC_MODEL | 具体车型 | "BYD Seal 在沙特上市" |
| INDUSTRY_CHAIN | 产业链 | "BYD 电池技术领先" |
| FINANCIAL | 股价/财报 | "BYD 股价上涨" |
| MIXED | 混合（无法区分主次） | - |
| OTHER | 其他 | - |

**判定规则**：
- 以报道中出现频率最高、篇幅最大的指涉层级为主；
- 若多个层级并列，编码"MIXED"。

---

### 3.2 主导框架（primary_frame）

**定义**：报道组织品牌信息的主导视角。

| 值 | 定义 | 特征词/线索 |
|----|------|-----------|
| TECH_LEADERSHIP | 技术领先 | 技术、创新、专利、刀片电池、续航、自动驾驶 |
| PRICE_ADVANTAGE | 价格优势 | 便宜、性价比、价格、补贴、入门级 |
| SAFETY_RECALL | 安全/召回 | 安全、召回、碰撞、缺陷、故障、保险 |
| AFTER_SALES | 售后/服务 | 售后、保修、服务、维修、经销商、充电 |
| ENVIRONMENTAL | 环保/可持续 | 环保、碳中和、可持续、绿色、排放 |
| POLICY_GEO | 政策/地缘 | 政策、关税、制裁、贸易、地缘、政府 |
| CULTURAL_CONFLICT | 文化冲突/误读 | 宗教、文化、习俗、斋月、清真、误解 |
| MARKET_COMPETITION | 市场竞争 | 市场、份额、竞争、超越、领先、排名 |
| OTHER | 其他 | - |

**判定规则**：
- 以报道首段和标题的主基调为准；
- 若报道整体偏中性，根据核心段落判断；
- 无法判断时编码"OTHER"。

---

### 3.3 次要框架（secondary_frame）

**定义**：报道中除主导框架外，明显出现的其他框架。

**格式**：用分号分隔，可多选。
**示例**：`TECH_LEADERSHIP; PRICE_ADVANTAGE`

**规则**：只编码明显出现（至少一个完整段落或显著篇幅）的次要框架。

---

### 3.4 情感倾向（sentiment_manual）

**定义**：报道文本对品牌的整体评价方向。

| 值 | 定义 | 特征 |
|----|------|------|
| Positive | 正面 | 称赞、肯定、看好、成功、领先 |
| Neutral | 中性 | 客观陈述、无明显褒贬 |
| Negative | 负面 | 批评、质疑、担忧、失败、落后 |

**判定规则**：
- 基于全文整体基调，而非单个句子；
- 中性报道占多数；
- 若正负面混合，以主导情感为准。

---

### 3.5 文化误读类型（misreading）

**定义**：因宗教/文化差异导致的品牌形象误读。

| 值 | 定义 | 示例 |
|----|------|------|
| FACTUAL_ERROR | 事实错误 | 误称斋月期间禁止驾驶电动车辆 |
| CONTEXT_MISPLACEMENT | 语境错置 | 用西方审美标准评价中东消费者偏好 |
| STEREOTYPICAL_ATTRIBUTION | 刻板化归因 | "中国制造=廉价低质" |
| KEY_CONTEXT_OMISSION | 关键语境遗漏 | 评价电动车时忽略宗教/气候因素 |
| NO_MISREADING | 无误读 | 准确呈现文化差异，或不涉及文化因素 |
| CANNOT_DETERMINE | 无法判断 | 信息不足，无法判定 |

**判定规则**：
- 只有报道明确涉及宗教/文化因素时才编码误读类型；
- 若报道未涉及文化因素，编码"NO_MISREADING"；
- 遇到边界案例，编码"无法判断"并记录证据。

---

### 3.6 误读证据（misreading_evidence）

**定义**：支持误读判断的具体文本片段。

**格式**：直接引用报道原文（阿语原文+中文翻译或英文原文）。

**示例**：
> 原文：`"السيارات الكهربائية الصينية لا تصلح لحرارة الخليج"`
> 翻译："中国电动车不适合海湾高温"

**规则**：
- 每条误读编码必须附证据；
- 证据片段应完整表达判断依据；
- 若无法引用，说明原因。

---

### 3.7 议题标签（topics）

**定义**：报道涉及的议题维度。

**格式**：多选，用分号分隔。

| 值 | 定义 |
|----|------|
| TECH | 技术 |
| PRICE | 价格 |
| SAFETY | 安全 |
| AFTER_SALES | 售后/服务 |
| ENVIRONMENTAL | 环保 |
| POLICY | 政策 |
| CULTURE | 文化 |
| RELIGION | 宗教 |
| MARKET | 市场 |
| OTHER | 其他 |

**规则**：
- 与框架不同，议题标签反映报道讨论的具体内容；
- 可同时出现多个议题；
- 至少编码 1 个议题。

---

## 四、边界案例处理

### 4.1 品牌指涉层级边界

- 若报道主要讨论 BYD 但提及 Tesla 作对比，品牌为"BYD"，指涉层级以 BYD 为准；
- 若报道讨论行业趋势，BYD 和 Tesla 均为案例，品牌为"BOTH"。

### 4.2 框架边界

- 若报道同时强调技术领先和价格优势，判断哪个在首段/标题中更突出；
- 若两者并列，选择更符合报道整体基调的框架。

### 4.3 文化误读边界

- 若报道只是提到"中国品牌在中东面临文化挑战"，但未具体展开，编码"无误读"；
- 若报道明确指出某个文化误读案例，编码相应类型；
- 若报道的"误读"其实是合理的跨文化观察，编码"无误读"。

## 五、编码员培训材料

### 5.1 预编码样本（50篇）

每个子语料库随机抽取 10-15 篇：
- BYD 阿语：12 篇
- BYD 英语：12 篇
- Tesla 阿语：13 篇
- Tesla 英语：13 篇

### 5.2 编码一致性计算

使用 Cohen's Kappa：

```
κ = (Po - Pe) / (1 - Pe)
```

其中：
- Po = 观察到的一致性
- Pe = 随机期望的一致性

**验收标准**：κ ≥ 0.70

### 5.3 争议解决

1. 两名编码员讨论分歧；
2. 若无法达成一致，提交第三名编码员；
3. 记录争议案例及解决方式，修订手册。
